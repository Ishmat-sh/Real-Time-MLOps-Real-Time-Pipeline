# Real-Time MLOps: Financial Fraud Detection Pipeline

Production-style, end-to-end streaming fraud detection: simulated live transactions flow through **Redpanda**, are enriched with historical context from **Feast**, scored by an **XGBoost** model behind **FastAPI**, and monitored with **Prometheus**, **Grafana**, and **Evidently AI**.

## Architecture

```
[Transaction Producer] ──► [Redpanda: raw-transactions]
                                    │
                                    ▼
                          [Stream Consumer] ──HTTP──► [FastAPI /predict]
                                                          │
                                                    [Feast + Redis]
                                                          │
                          [Prometheus] ◄── metrics ───────┘
                                │
                          [Grafana Dashboard]
                                │
                          [Evidently Drift Monitor]
```

## Quick Start

**Prerequisites:** Docker Desktop (or Docker Engine + Compose v2), 8 GB+ RAM recommended.

```bash
cd fraud-detection-pipeline
docker compose up --build
```

Startup order:

1. **Redis** + **Redpanda** come online
2. **feast-init** seeds user features and materializes to Redis
3. **train** fits XGBoost and writes `inference/models/fraud_model.pkl` + baseline parquet
4. **inference**, **producer**, **consumer**, **prometheus**, **grafana**, **drift-monitor** start

First full build may take several minutes.

```
│   └── drift/              # Stage 5: Evidently data drift checks
└── data/baseline/          # Training feature reference (generated by train)
```

## Stages (Master Plan Mapping)

| Stage | Component | What it does |
|-------|-----------|--------------|
| 1 | `producer/producer.py` | Generates realistic transactions (~50/s) to `raw-transactions` |
| 2 | `feast/feature_repo/` | Serves `user_avg_spend_30d`, `user_tx_count_30d`, `user_failed_logins_24h`, `user_max_spend_7d` from Redis |
| 3 | `training/train.py` | Trains XGBoost, saves `.pkl`, exports drift baseline parquet |
| 4 | `inference/app/main.py` | `/predict` merges live + Feast features, returns `approved` / `flagged` |
| 5 | Prometheus + Grafana + `drift_monitor.py` | Ops metrics, dashboards, periodic Evidently drift reports |

## Configuration

Environment variables (see `.env.example`):

- `TRANSACTIONS_PER_SECOND` — producer throughput (default `50`)
- `FRAUD_THRESHOLD` — probability cutoff for `flagged` (default `0.5`)
- `CHECK_INTERVAL_SECONDS` — drift monitor cadence (default `120`)

## Observability

**Grafana** dashboard *Fraud Detection Pipeline* includes:

- Transaction throughput (predictions/sec)
- Fraud flags/sec and fraud ratio
- API latency p95 / p99
- Feast feature fetch latency

**Drift monitor** compares production samples (`drift_samples/production_samples.jsonl`) against `data/baseline/training_features.parquet`. When dataset drift share exceeds the threshold, it logs an alert simulating a retraining trigger. HTML reports are written inside the `drift-monitor` container under `/app/drift_reports/`.

```bash
docker compose exec drift-monitor ls /app/drift_reports
```
